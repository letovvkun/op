# LetovShiyori — статический сайт проекта перевода One Piece

Сайт остаётся набором статических HTML/CSS/JavaScript-страниц. Он не превращается в универсальный видеосервис: главная, каталог тайтлов, страницы проектов, информационная страница, торрент-трекер и мини-игра сохраняют своё назначение. Сборщик и frontend-фреймворк не требуются.

## Структура проекта

```text
js/
├── core/          # Firebase SDK-адаптер, DOM, хранилище, кэш, ошибки, UI
├── components/    # Общий поиск, отметки просмотра и список серий
├── services/      # Данные Firestore, настройки сайта, правила серий, плеер и телеметрия
└── pages/         # Композиция поведения конкретных страниц
```

Подробные границы слоёв и правила для следующих изменений описаны в `ARCHITECTURE.md`.

## Основные договорённости

- Firebase SDK и конфигурация подключаются через `js/core/firebase.js`. Страницы не импортируют Firebase-адаптер напрямую; доступ к Firestore находится в `services/`.
- HTML-страница отвечает за отображение, а сервис — за формат и выполнение запросов.
- Кэшируемые запросы проходят через `js/core/data-cache.js`: TTL по умолчанию — 5 минут, одинаковые параллельные запросы объединяются, а валидные результаты `null` тоже кэшируются.
- Firebase Analytics загружается только при первом событии и только если поддерживается браузером; её недоступность не блокирует Firestore.
- Для чтения и записи Web Storage используется `js/core/storage.js`. Недоступность хранилища не должна ломать страницу или игру.
- Значения Firestore нельзя без проверки вставлять в `innerHTML`. Для текста используйте `textContent`, для HTML-строк — `escapeHTML()` и проверку URL.
- Внешние видеохостинги остаются гибкими: iframe принимается с любого валидного HTTPS-источника, но его HTML не исполняется напрямую.
- Визуальные изменения не являются частью технического рефакторинга. Сохраняйте существующую разметку, стили и поведение, если задача явно не требует другого.

## Локальная проверка

Требуется Node.js 22 или новее. Установка зависимостей не нужна:

```bash
npm test
```

Тесты проверяют безопасную DOM-обработку, URL, Web Storage, кэш и конкурентные запросы (включая принудительное обновление поверх старого запроса), жизненный цикл общего плеера, общий браузер серий (поиск, сортировка, навигация, пагинация и отметки просмотра), фильтрацию публикаций, базовую целостность HTML-тегов, ссылки и фрагменты HTML, локальные CSS-ресурсы, уникальность id, alt у изображений, inline-скрипты, Sitemap, достижимость статических и динамических модулей, циклические импорты и границы Firebase-слоёв.

## Публикация

GitHub Actions workflow `.github/workflows/static.yml` проверяет синтаксис JavaScript и запускает `npm test` перед деплоем. В Pages попадают только публичные HTML-файлы, `css/`, `js/`, `CNAME`, `robots.txt`, `sitemap.xml` и `veo-veo.txt`. Тесты, документация для разработки и служебные заметки в публикацию не включаются.

## Firebase и телеметрия

Firestore Security Rules уже настроены владельцем проекта: публичное чтение разрешено, запись доступна владельцу через административный интерфейс. Правила, схема документов и модель доступа этой итерацией не менялись.

Телеметрия сохранена и продолжает писать статистику в `settings/telemetry`. Проверка поддержки Firebase Analytics теперь изолирована: блокировщик или неподдерживаемая среда не должны мешать работе Firestore.
